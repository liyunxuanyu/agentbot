# 执行命令

对应工具：`run_shell`。

## 什么时候用

- 需要构建、跑测试、看 git 状态、检查环境（`node -v`、`python --version`）时。
- 需要做的事有现成工具时（读文件、找内容）**优先用工具**，不要用 shell 绕一圈：
  `cat` → `read_file`，`grep` → `grep`，`ls` → `list_dir`。

## 工作顺序

1. 先用 `list_dir` 或 `read_file` 看目录结构与配置文件（`package.json`、
   `pyproject.toml`），确认命令入口和包管理器。
2. 再跑最小可验证的命令（先 `--version` / `--help`，再跑真任务）。
3. 长时间命令给足超时，不要用会一直挂住的前台进程（`dev server`、`watch`）。
   需要后台运行就明确说明，并让用户决定。

## 常见错误

- **在错误的目录里跑**：cwd 固定为会话工作区；需要子目录时在命令里显式 `cd sub && …`
  （同一条命令内，不要依赖上一条命令的 cd）。
- **交互式命令**：`git rebase -i`、`npm init` 这类会等待输入的会挂到超时；
  用非交互参数（`--yes`、`-m`）。
- **一次跑一大串 `&&`**：失败时不知道是哪一步坏的；分步跑，每步看输出。
- **忽略退出码**：非零退出码就是失败，先读 stderr 再决定下一步。

## 边界

- 命令在会话工作区内执行；越界的路径会被权限层拒绝。
- 执行命令需要用户批准（计划模式下工具不可用）。被拒绝时换做法或说明原因。
- 输出会截断；需要完整输出时重定向到文件再用 `read_file` 读。
