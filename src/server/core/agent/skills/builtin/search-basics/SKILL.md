# 查找

对应工具：`grep` / `list_dir`。

## 什么时候用

- 不知道文件在哪 → 先 `list_dir` 看目录，再 `grep` 按内容定位。
- 找函数/变量/字符串出现的位置 → `grep`。
- 确认某个目录下有哪些文件、是不是空目录 → `list_dir`。

## 工作顺序

1. **先看结构**：`list_dir(".")` 或 `list_dir("src")`，确定候选目录。
2. **再搜内容**：`grep(pattern, path?)`。pattern 是正则，注意转义
   （搜字面量 `a.b` 要写 `a\.b`）。
3. **收窄范围**：给出 `path` 限定目录，比全仓搜索快很多；匹配太多时
   用更具体的 pattern，不要直接翻 200 条结果。

## 常见错误

- **正则写太宽**：`foo` 会命中 `foobar`、注释与测试；用词边界 `\bfoo\b`
  或带上下文（`function foo`）。
- **大小写**：默认区分大小写；不确定时在 pattern 里用 `[Ff]oo` 或先按小写搜。
- **忽略隐藏/忽略目录**：`.git`、`node_modules` 里的命中通常不是你要的；
  用 `path` 限定到源码目录。
- **搜完不读**：grep 只给行号和片段，要理解上下文还得 `read_file` 看那一段。

## 边界

- 只能搜工作区内的路径；越界会被拒绝。
- 匹配条数有上限（默认 200），结果被截断时会标注；这时应当收窄 pattern，
  而不是换更大上限。
- 这两个工具都是只读，计划模式下仍可用。
