# AgentBot 视觉设计系统 · terminal-native

> variant = `terminal`。令牌文件：`agentbot-tokens-terminal.css`。输入：`agentbot-02-ux.md`（10 页 / 6 流程 / 9 类事件）、`agentbot-01-prd.md`、`board/product-positioning/03-decisions.md`（权限三档超时）。

## 1. 设计方向

**气质**：你的 agent 会话被放进了一个有布局能力的终端。视觉血统来自 tmux 分屏、lazygit 的树形 gutter、htop 的密排数字表，不是 SaaS 后台。

**为什么适合**：目标用户（A 独立开发者、C 折腾者）整天在终端里跑 agent，他们的眼睛已经校准到「等宽 / 暗底 / 边框即分区」。产品要做的是**不打断这种肌肉记忆**——运行时徽标、事件树、token 计数都用他们已有的读法呈现，而不是翻译成圆角卡片。

**牺牲了什么**：① 对 B 类非工程用户（产品/运营）门槛明显更高，等宽 + 方括号需要学一次；② 长段中文在等宽下比无衬线疲劳；③ 只有一个暗色主题，白天户外屏不可用；④ 密排意味着扫读靠分隔线而非留白，密集恐惧者不适。这些是自觉的取舍，不是遗漏。

**强调色选型**：`#3DBFB8`（HSL 177°），是 ANSI bright cyan 向绿偏移 8° 的暗化版。理由：① 全色相盘里只有青绿这一条道不会与三个语义色打架——绿（135°）、琥珀（45°）、红（8°）都已占用，选蓝会落进「AI 产品默认蓝」，选紫是明令禁区；② 177° 比 SaaS 的 195° 电光青更旧、更接近 phosphor 屏；③ 与 success 绿相隔 42°，且两者**永不同行出现**（成功色只做 2–3 字符的状态词，强调色只做结构性标记：竖条、光标、焦点环）。明确不用：`#7C5CFF`（靛蓝，AI 陈词）、`#D97757`（暖陶，Anthropic 味）。

**对比度实测**：正文 fg-1/bg-1 = **13.53:1**；次要 fg-2 = **7.44:1**；三级 fg-3 = **5.22:1**；禁用 fg-4 = **3.31:1**（≥3:1，符合「禁用态仍需可辨」）；accent/bg-2 = **8.08:1**；danger/bg-2 = **5.60:1**；accent 上的深字 `#07090B`/accent = **8.87:1**。

## 3. 字体系统

**字体族**：`--font-mono` = `"JetBrains Mono", "IBM Plex Mono", "Cascadia Mono", "Sarasa Mono SC", "Noto Sans Mono CJK SC", ui-monospace, Consolas, monospace`。选 JetBrains Mono 而非 Berkeley Mono：开源可随包分发、`0/O` 与 `1/l/I` 的区分度足够、有真正的 tabular figures 与 slashed zero。CJK 用 **Sarasa Mono SC**（等宽 + 中文，Latin 部分与 JetBrains 度量接近）——**必须随包内置**，否则中文回落到系统默认字体，全角/半角混排会破坏 gutter 对齐（见 §9）。全程无无衬线正文字体，无第二字族。

| 令牌 | px | 行高 | 字重 | 用途 | 字距 |
|---|---|---|---|---|---|
| `--text-2xs` | 11 | 15 | 400 | 徽标、表格头、时间戳、gutter 标签 | +0.02em |
| `--text-xs` | 12 | 17 | 400 | 事件摘要、按钮、卡片元信息 | 0 |
| `--text-sm` | 13 | 19 | 400 | 导航、表格单元、默认 UI 文字 | 0 |
| `--text-md` | 14 | 20 | 400 | 消息正文、Turn 正文、输入框 | 0 |
| `--text-lg` | 16 | 22 | 600 | 区块标题（`/bots` 页头、面板标题） | -0.005em |
| `--text-xl` | 20 | 26 | 600 | 页面标题（Bot 名、`/usage`） | -0.01em |
| `--text-2xl` | 24 | 30 | 700 | 数字焦点：总 token、Bot 详情名 | -0.015em |

**数字排版**：全部 `font-variant-numeric: tabular-nums`，数字列 `text-align: right`。Turn 尾用量用短式 `1.2k/0.4k`（≤3 位有效数字 + k），`/usage` 表格用全式 `1,204`（千分位，不缩写）。耗时：`<60s` 用 `12.4s`；`<60m` 用 `1m04s`；更久 `1h20m`。倒计时固定 `mm:ss` 且等宽右对齐，避免数字跳动导致按钮位移。

## 4. 间距与栅格

**刻度**（基准 4px，另设 2/6 两个半档给密排）：`2 / 4 / 6 / 8 / 12 / 16 / 24 / 32 / 48`。2 只用于行内微调（徽标内边距），6 只用于紧凑块内间距，48 只用于空态与页面级留白。

**布局栅格**：`240px 导航 | 1fr 主区 | 320px 右栏`，三者之间**不是 gap 而是 1px 实线**（`border-right` / `border-left`），视觉上像 tmux 的三个 pane 共享边框。1024–1280 导航收为 64px，**不显示图标，显示三字母标签**（`bot` `cht` `asm` `sch` `usg` `set`）——遵守「禁止 emoji 图标」，同时保留可读性。窄屏 <1024 右栏变全屏覆盖层，导航变抽屉。

**密度规则**：事件行 24px 高、卡片内边距 12px、表格行 28px——这三处必须紧，靠 1px 线分隔而非空隙。必须留白的三处：空态 48px、页面标题下方 24px、危险操作区上方 32px（给「停一下」的余地）。

## 5. 组件规格

**Bot 卡片**：bg-2 / 1px `border` / 内边距 12px / 无圆角无阴影 / 5 行固定（身份 20 + 人格 19 + 运行时 19 + 位置 19 + 状态 19，合计 132px）。网格用 `gap:1px; background:var(--color-border-subtle)` 让相邻卡片共享缝隙，形成连续栅格（TUI pane 的观感）。状态：默认如上；悬停 bg-3 + 边框 `border-strong`；键盘焦点 2px accent `outline-offset:-2px`（内嵌，不撑开布局）；生成中左侧加 2px accent 竖条 + 状态词 `[run]`；运行时不可用则顶部加 22px danger 横幅行。整卡是 `<a>`，次操作（详情/派任务）只在悬停时出现在右下，24px 高。

**Turn 头**：高 32px，bg-1（不透明，吸顶时盖住滚动内容，绝不毛玻璃），下边框 1px `border-subtle`。内容：24px 方形头像（直角，bg-3 底 + 1 字符首字）+ Bot 名 13/600 fg-1 + `·` + 运行时徽标 + 模式 + Session 标记（仅变化时出现）。流式中的 Turn 整体加 2px accent 左边框。折叠后 Turn 头变 28px 单行，右侧附 `✓ 12.4s · 1.2k/0.4k`。

**事件折叠块**：行高 24px，grid `2ch gutter │ 2ch 符号 │ 1fr 摘要 │ auto 元信息`。默认摘要 fg-2 12px，右侧 `▸` 2ch fg-3。展开：整块 bg-3，上下 1px `border-subtle`，内边距 8px 12px，`max-height:320px; overflow:auto`，内容 12/17 fg-2，`white-space:pre`。悬停 bg-2；焦点 2px accent 内嵌环。连续同类事件（如 3 次 Read）合并为 `→ 3 次工具调用 ▸`，展开后再逐条。

**消息（非气泡）**：助手消息无背景、无边框，gutter 3ch 内一个 `│`（fg-4），正文 14/20 fg-1，**最大 44 个全角字符宽**（`max-width:88ch` 的一半，因为中文占 2ch）。用户消息整行 bg-2，上下 1px `border-subtle`，左 2px `border-strong`，gutter 内 `>` 用 accent，内边距 8px 12px。不用气泡尾巴、不用头像列（头像在 Turn 头已出现一次）。

**权限卡片**（三态）：
- *阻断型*：外框 1px `accent`，左 3px accent，bg-2，标题行 bg `accent-bg`（`! 待你批准 · 写文件` + 右对齐倒计时 `01:47`）。正文区：动作目标在 bg-3 上 12px 单行，超长中段省略。按钮行 4 个，`批准一次` 为 primary（前缀 `[A]`），其余 secondary/ghost。占满消息流宽度，`position:sticky; bottom:输入区高度`。出现时输入框锁定为 bg-1 + fg-4 文案。
- *挂起型*：同上但外框与竖条改 `warning`，标题 `! 已挂起 · 剩余 23h 12m`，无倒计时紧迫感，输入框**不锁**，Turn 头加 `[hold]`。
- *失效型*：外框 `border-subtle`，bg-1，全部文字 fg-4，四个按钮 disabled，标题 `✗ 请求已失效`，无竖条。
- *自动处置*：不成卡，流内一行 24px：`✓ 自动批准（已记住） · 写 src/a.ts`，fg-3，可展开看审计字段。

**输入区**：底部固定，bg-2，上边框 1px `border`；聚焦时该边框变 accent（1px，不改变高度）。gutter 3ch 放 `>`（accent）。textarea 无边框，14/20，1–8 行自增，内边距 12px。工具行 28px：左 = Bot 名 + `@` + 执行位置；右 = `发送 ⏎`（primary，28px）或生成中替换为 `停止 esc`（secondary，位置不变）。锁定态显示 `等待你批准，无法继续发送`，整块 bg-1。

**按钮**：高 24px(sm)/28px(md)，内边距 0 8/0 12，直角，1px 边框，12/600。
| 类型 | 默认 | 悬停 | 按下 | 禁用 | 焦点 |
|---|---|---|---|---|---|
| primary | bg accent / 字 bg-0 / 框 accent | bg `#4ACFC8` | bg `#2FA8A2` | bg bg-3 / 字 fg-4 / 框 border-subtle | 外 2px accent 环，offset 1px |
| secondary | 透明 / 字 fg-1 / 框 border | bg bg-3 / 框 border-strong | bg bg-4 | 同上禁用 | 同上 |
| danger | 透明 / 字 danger / 框 danger | bg danger-bg | bg `#3A1B17` | 同上 | 同上 |
| danger-confirm | bg danger / 字 bg-0 | bg `#F07A6C` | bg `#C24A3F` | — | 同上 |

**状态徽标**：11px，1px 边框，内边距 0 4px，高 16px，**方括号本身就是符号**：`[run]` accent+accent-bg / `[idle]` fg-3+border-subtle / `[queue]` warning+warning-bg / `[down]` danger+danger-bg / `[hold]` warning 仅描边。全部小写，不靠颜色区分（颜色是二次编码）。

**能力徽标**：三枚固定顺序 `[plan✓] [perm×] [resume?]`。`✓` fg-1、`×` fg-3、`?` warning。11px，无底色，只有 1px `border-subtle`。未知用 `?` 而非隐藏（对应 UX 原则 2）。与 Bot 卡片「运行时」行同一基线，右对齐。

**表格行**（`/usage`）：行高 28px，1px `border-subtle` 下划线，无斑马纹。表头 24px，bg-1，11px fg-3 小写，吸顶。数字列右对齐 + tabular；Bot 名与运行时列左对齐。悬停 bg-2。列之间不加竖线，仅在「模式倍率」组前加 1px `border` 分隔。已删除 Bot 整行 fg-3 + 行尾 `[已删除]`。

**空态**：左对齐面板（不居中——居中空态是 SaaS 的默认手势），bg-1，1px `border-subtle`，内边距 32px。结构：`∅` 24px fg-4 在 3ch gutter 内，标题 14 fg-1，一行说明 12 fg-3（≤40 字），一个主按钮。禁止插画。

**导航项**：高 28px，内边距 0 12px，13px fg-2，右对齐计数（fg-3，tabular）。激活：bg-4 + 字 fg-1 + 左 2px accent + 前缀 `▸`。悬停：bg-2 + fg-1。焦点：2px accent 内嵌环。待批计数用 warning 色，执行中计数用 accent 色——两者都是数字，颜色只是第二编码。

**Session 分隔条**：全宽一行 22px，上边框 1px `dashed` `border`，左侧标签 `新 Session · 已重建上下文（人格 + 记忆 + 最近 20 条）` 11px fg-3，bg-1 盖住虚线。只在 L2 状态变化时出现。

## 7. 动效

全局原则：只动「刚发生的事」，不动布局。时长全部 ≤240ms，缓动一律 `linear`（终端没有贝塞尔曲线）。

| 动效 | 时长 / 缓动 | 说明 |
|---|---|---|
| 流式光标 `▌` | 1000ms `steps(1,end)` 无限 | 2px 宽，accent，50% 处消失；Turn 结束立刻移除 |
| 事件出现 | 240ms linear | 新行背景从 bg-3 淡到透明（一次「打印」高亮），不做位移与缩放 |
| 权限卡片进入 | 120ms linear | 透明度 0→1 + 左竖条 2px→3px；不弹跳、不缩放 |
| Turn 折叠/展开 | 120ms linear | 高度过渡；折叠时先收起内容再改头行高度，避免文字挤压 |

`prefers-reduced-motion: reduce`：光标改为常亮实心（不闪）；所有 `transition` 设 `0ms`；新事件高亮取消，改为该行左侧 1px accent 竖条保留到下一次交互（状态仍可辨，不依赖动画）；自动展开（群聊轮到下一 Turn）改为不自动滚动。

## 8. 与 UX 五条原则的对应

1. **Bot 是主角，运行时是属性**：每张卡片第一行永远是 Bot 名（14/600 fg-1），运行时只以 12px fg-2 出现在第三行、且前缀是 `运行时` 三个汉字而非图标；导航里没有任何运行时入口。
2. **能力可见而非缺失**：能力用 `[plan✓] [perm×] [resume?]` 三枚固定位置徽标，未知是 `?` 而不是空白——空白会被读成「不支持」。流内不出现的类型则完全不出现（无灰块）。
3. **治理在主流程内**：权限卡片长在消息流里、和 Turn 同宽、粘在输入框上方；审计只以一行折叠行回落到流内；设置页只有默认值与回看。
4. **一次只展开一层**：靠 gutter 的层级符号实现——Turn 用 `▍`、事件用 `→ ~ # ←`、事件内容缩进 4ch 且 bg 变深一档。深度上限 2 级（事件 → 参数），不再有第三层。
5. **缺席要可解释**：所有「没发生」都渲染成一行带原因的灰色文字（`~ 本轮未发言 · 主持人判断与任务无关`），用 `~` 符号与正常事件区分；永不渲染空白区域。

## 9. 局限与风险

| 风险 | 具体后果 | 缓解 |
|---|---|---|
| 非技术用户（U4 产品经理）门槛 | 方括号、`[run]`、`resume?` 需要学习，首启可能懵 | 方括号内一律用完整英文词不用缩写；首启向导里 `?` 悬停给一句中文解释；主操作按钮（批准/发送/新建）不用任何符号前缀 |
| 中文字体缺失导致 gutter 错位 | 无 Sarasa Mono SC 时中文按比例宽度渲染，2ch 对齐崩坏 | **随包内置 Sarasa Mono SC**（subset 到 GB2312 常用字，约 1.2MB）；`font-synthesis:none`；gutter 用 `ch` 但只在纯 ASCII 行内依赖精确宽度 |
| 长文本可读性 | 等宽 13px 读 500 字的中文报告会疲劳 | 消息正文用 14/20（不是 13），最大 44 全角字符；超过 30 行的产出引导去 `/assignments/:id`，那里用 14/22 + 段落间距 12px |
| 375px 窄屏 | 44 全角字符需 616px，必然折行到 3 行以上，密度优势消失 | 375px 下正文降 13/19、导航变抽屉、右栏变覆盖层；表格允许横向滚动并给 1px 滚动提示；权限卡改为底部全宽固定条 |
| 只有暗色 | 强光环境、投影场景不可读 | 明示为自觉取舍；不提供浅色主题（浅色会摧毁「终端」的一致性），但在 `/settings` 提供对比度增强开关（fg-3 → fg-2） |
| 强调色过载 | 开发容易把 accent 当「好看的颜色」到处用，三处状态语义失效 | 令牌命名 `--color-accent` 不带语义，配套注释明确「仅用于 focus / running / pending-decision」；评审时统计 accent 出现次数，超过每屏 3 处即判违规 |
