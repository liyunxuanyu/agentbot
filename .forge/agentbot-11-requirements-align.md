# AgentBot 变更需求对齐 · 会话控制 / 记忆作用域 / 管理员 Bot

> 依据：用户 2026-10-26 的原话与四个分叉决策。本文是**本轮口径源头**。
> 工作流据此产出 `.forge/agentbot-12-change-spec.md`（PM）与 `.forge/agentbot-13-impact.md`（架构）。
> 与旧 PRD / UX / 架构冲突处，以本文为准；差异必须在变更规格里列成对照表。

## 0. 本轮范围：只做内置引擎

所有需求都落在 **builtin 运行时**（`adapters/channels/builtin/driver.ts` + `core/agent/*`），不碰 ACP / Codex native / CLI 兜底三条通道。

| 能力 | 内置引擎（本轮做） | 其它运行时（本轮不动） |
|---|---|---|
| 工作区 | 会话级 cwd，直接生效 | 沿用 Bot 级 `repo_path` + worktree |
| 模型切换 | 会话内可切供应商 + 模型 | 不可切，选择器禁用并说明原因 |
| 四档权限 | 生效（工具调用在进程内裁决） | 不可切，沿用各运行时自身权限模型 |
| 记忆隔离 / 压缩 / 缓存统计 | 生效（产品层，与运行时无关） | 同左（产品层逻辑共用） |
| 管理员 Bot | `create_bot` 是内置工具 | 同左（工具由内置引擎提供） |

范围收窄后 R1 的硬阻断消失：内置引擎没有 worktree，工作区就是进程 cwd；CLI 运行时「无权限通道时强制 `repoPath`」的现状保持不动。

## 1. 一句话

Bot 从「绑死一个项目目录的执行体」变成「可以在任意工作区里被召唤的同事」：
创建 Bot 不再需要项目地址；工作区下沉到会话/群聊；记忆按会话隔离；
会话内可切模型与四档权限；全局有一个（或多个）管理员 Bot 负责建 Bot；
长会话要能压缩上下文，并能看见缓存命中。

## 2. 用户原话（不改写）

> 我创建bot的时候可以不用指定项目地址，这个不是必须的，但是我进入会话或者群聊进行工作那些工作的时候，需要指定工作区路径，也可以默认不用指定，还有就是，现在单个bot会话里面不能进行模型切换，还有就是全局默认一个管理员bot，这个bot可以去帮我创建其它bot，问我要创建什么bot这些，来进行bot创建，管理员可以不用是一个，还有就是现在单个会话里面还有单个bot不能随时更改权限就是那种完全访问，计划模式、自动模式、还有变更前确认的这种切换

> 选择1，并且，每个独立的会话，或者独立的群聊，即便有相同的bot，各自的记忆那些也要隔离开，对了记得，还需要做一下上下文压缩，还有缓存命中率那些

## 3. 已拍板（Q15–Q18）

| 编号 | 问题 | 决定 |
|---|---|---|
| Q15 | 工作区作用域 | **会话/群聊级**（`channels.workspace_path`），群聊内多 Bot 共用；Bot 的 `repo_path` 降级为可空「默认工作区」 |

## 4. 需求条目与验收锚点

| 编号 | 需求 | 验收锚点（可观察） |
|---|---|---|
| R1 | 创建 Bot 不需要项目地址 | 内置引擎 Bot 不填 `repoPath` 能创建成功并立即可用；Bot 卡片无默认工作区时显示「未设置默认工作区」，不显示空路径占位。CLI 运行时保持现状 |
| R2 | 会话/群聊指定工作区 | 会话头部可设置/更换工作区；不设置时按回退链解析；路径不存在/不可写时明确报错，**不静默降级**。内置引擎直接用作 cwd，不建 worktree |
| R3 | 记忆按会话隔离 | 同一 Bot 在会话 A 的自动摘要与手动记忆，不出现在会话 B 的注入里；群聊内共享该群聊作用域 |
| R4 | 会话内切模型 | 会话设置栏可切供应商 + 模型；只影响后续轮次；内置引擎即时生效；跨协议给出「建议新开会话」提示 |
| R5 | 会话内切四档权限（选择器常显，见 §4.1） | 随时可切且当前档位可见；plan 下写工具直接被拒并说明原因（不弹权限卡）；full 下直接执行但写审计；auto 边界内自动批、越界直接拒绝并说明原因（不弹卡，见 §4.2 口径）；confirm 保持现状 |
| R6 | 管理员 Bot | `role='admin'`；持 `create_bot` 工具；创建前在对话里问清要建什么，创建后回执；可多个；非管理员调用 `create_bot` 必须被拒 |
| R7 | 上下文压缩 | 可感知（流内插入「已压缩 N 条 → 摘要 M 字」标记）、可手动触发、阈值可配；压缩后继续对话不重复膨胀系统提示 |
| R8 | 缓存命中率 | `usage_records` 记录缓存读/写 token；`/usage` 展示命中率；OpenAI 与 Anthropic 两种口径归一 |

### 4.1 权限模式选择器（像 ZCode 那样常显在会话里）

**位置**：输入区左侧，`@` 按钮旁边，与发送按钮同一行。DM 里直接作用于该会话；群聊里作用于「当前展开的 Bot」，菜单第一项是「应用到本群全部 Bot」。

**形态**：胶囊按钮，高 30，`--radius-md`，`--color-surface-2` 底，内容为 8px 语义色点 + 模式名 + `chev`。点击弹出下拉（`--shadow-overlay`，r14），四行，每行 = 模式名 + 一句说明；当前项左侧打勾。

| 模式 | 胶囊文案 | 下拉说明 | 点色 |
|---|---|---|---|
| plan | 计划模式 | 只读：不改文件、不跑命令，先出方案 | `--color-info` |
| confirm | 变更前确认（默认） | 写文件、跑命令前都问你 | `--color-primary` |
| auto | 自动模式 | 边界内的写操作自动批准；越界直接拒绝并说明原因 | `--color-warning` |
| full | 完全访问 | 不再询问，所有动作直接执行并记审计 | `--color-danger` |

**行为**：

> **auto 越界口径（R5，2026-10-28 定稿）**：越界写**直接拒绝**、不弹卡。理由：auto 的语义是「别烦我」，越界弹卡等于退回 confirm；越界本身是配置问题（该目录不在 Bot 边界里），提示用户去改边界比当场追问更可操作。拒绝原因写进 tool_result 回灌给模型，模型会换做法或说明缺什么权限。


- 切换立即生效，不需要二次确认；切到 `full` 时胶囊变 danger 色并保持醒目。
- 生成中也允许切：只影响尚未裁决的工具调用（G3）。
- 切到 `plan` 时若有挂起的写类权限卡，直接置为 rejected，并在流内插一条系统块「已按计划模式拒绝 N 个挂起请求」。
- 只对内置引擎 Bot 可用；CLI/ACP/native 会话显示禁用态，tooltip「该运行时由 CLI 自身管理权限」。
- 键盘：`Shift+Tab` 在四档间循环，与 ZCode 一致。
- 权限模式是会话属性（`sessions.permission_mode`），群聊里每个 Bot 的会话各自独立。

## 6. 缺口与建议口径

以下是用户原话没有覆盖、但不定就会各自实现的点。**建议口径**交给 PM 写进规格、架构师写进影响分析；
标「需用户确认」的属于不可逆或产品取向，走 gated 确认。

| 编号 | 缺口 | 建议口径 |
|---|---|---|
| G1 | 旧记忆怎么回填作用域 | `scope='bot'` 视为「该 Bot 的全局记忆」，历史行全部回填 `bot`；新写入默认 `session`（群聊为 `channel`）。这样老数据行为不变、新数据隔离 |
| G2 | 新会话的权限模式从哪继承 | 优先级：会话显式设置 → Bot 默认（新增 `bots.permission_mode`）→ 全局默认 `confirm` |
| G3 | 生成中切模式怎么生效 | 立即对**尚未裁决**的工具调用生效；已在执行的不回滚。切到 plan 时挂起的写类请求直接置为 rejected 并留审计 |
| G4 | 管理员 Bot 自己的权限边界 | 管理员只是多一个 `create_bot` 工具，**不自动获得 full**；`create_bot` 本身是写动作，照样受四档约束（plan 下被拒）。管理员不能改别的 Bot 的权限（本轮不做提权链） |
| G5 | 压缩触发与可见性 | 阈值按上下文窗口占用比（默认 70%）自动触发，也可手动；摘要用当前会话模型；流内插标记，原文仍留在 events 里可展开，但不再注入 |
| G6 | 缓存命中口径 | OpenAI 取 `prompt_tokens_details.cached_tokens`，Anthropic 取 `cache_read_input_tokens`；命中率 = 缓存读 / (输入 + 缓存读)；缺失时显示「未上报」而非 0 |
| G7 | 群聊共用工作区的并发写 | 内置引擎没有 worktree，群聊里所有 Bot 共用同一 cwd。默认由主持人串行；若开启「全员回复」，**写类工具在群聊级串行**（读不串），不做文件锁 |
| G8 | 工作区校验强度 | 必须存在、是目录、可写；**不要求 git**（内置引擎不用 worktree）。CLI 运行时维持原样（要求 git 才能建 worktree） |
| G9 | 会话级模型覆盖的持久化 | 存 `sessions.provider_id/model`；新会话默认取 Bot 的 `provider_id` + 该供应商默认模型；会话内切换只写当前会话 |
| G10 | 群聊里谁的工作区生效 | 群聊一个 `workspace_path`，全员共用；DM 的 `channels.workspace_path` 即该会话工作区 |

## 7. 明确不做

- 不做多用户 / 账号体系（沿用 Q3）
- 不做会话内切换**运行时**（运行时仍是 Bot 属性；本轮只切模型）
- 不做压缩历史版本回看与「回滚到压缩前」（原文可展开，但不重新注入）
- 不做缓存命中的费用折算（只统计 token 与比率）
- 不做管理员之间的提权链、不做 Bot 权限委派
- 不做群聊内按 Bot 分工作区（群聊共用同一 cwd）
- 不给 CLI / ACP / native 运行时加模型切换或权限模式（界面上显示禁用态与原因）

## 8. 与现有文档的差异（必须进变更规格的对照表）

| 旧口径 | 新口径 | 出处 |
|---|---|---|
| Bot 必须有项目路径（CLI 运行时强制） | 可空；工作区在会话/群聊 | R1/R2 |
| 记忆按 Bot 注入 | 按作用域注入（session/channel/bot） | R3 |
| 模型是 Bot 属性 | Bot 默认 + 会话覆盖 | R4 |
| 权限是 Bot 级边界 + 三档超时 | 再加四档**模式**，会话级可切 | R5 |
| 无管理员概念 | `role=admin` + `create_bot` | R6 |
| 上下文只靠截断 | 可压缩 + 可感知 | R7 |
| 用量只记 in/out | 加缓存读/写 | R8 |

## 9. 不可逆清单（逐条确认，不打包）

1. **迁移 v3**：`sessions` 加 4 列、`channels` 加 1 列、`bots` 加 2 列（`role`、`permission_mode`）、`memory_entries` 加 `scope`/`channel_id`、`usage_records` 加缓存列与 `model`；全部可空或带默认值，回填规则见 G1
2. **管理员种子**：首次启动若已配模型且无 `role='admin'`，种一个管理员 Bot
3. **记忆回填**：历史记忆统一回填 `scope='bot'`（不改内容，只改作用域）
