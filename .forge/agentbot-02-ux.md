# AgentBot 体验设计
> 输入：`agentbot-01-prd.md`、`agentbot-00-brief.md`、`agentbot-ref-research.md`。只定结构、路径与反馈；不定配色、字体、尺寸与实现。

## 1. 设计原则
| # | 原则 | 违反会怎样 |
|---|---|---|
| 1 | **Bot 是主角，运行时是属性。** 先出现「谁」，再出现「在什么上跑」；运行时只以徽标挂在 Bot 名下，永不成为导航对象。 | 用户按进程理解产品，退化为 agent 启动器。 |
| 2 | **能力可见，而非能力缺失。** 运行时没有 plan，流里就根本不出现计划块；能力本身在 Bot 详情如实写「支持 / 未知」，未知 ≠ 不支持。 | 出现假按钮或灰块，用户以为产品坏了（brief C3）。 |
| 3 | **治理在主流程内，不在设置里。** 权限卡片、边界拒绝、注入截断、resume 降级都出现在对话流；设置只放默认值与审计回看。 | 用户在设置里批权限看不到上下文，无人值守被静默拦死。 |
| 4 | **一次只展开一层。** Bot 卡不显示事件，会话不显示记忆全文，事件不自动展开参数；每层只给下一层入口。 | 三层混在一屏，群聊时信息密度失控。 |
| 5 | **缺席要可解释。** 没发言、没回复、没权限请求，都要给一句原因（主持人理由 / 能力未上报 / 边界拒绝）。 | 用户分不清「没发生」和「坏了」。 |

## 2. 信息架构

### 2.1 页面树（10 页 = PRD 9 页 + 补 1 页）
```
/                   有 Bot → /bots；无 Bot → /setup
/setup              L0 首启向导（探测 → 建 Bot → 首条消息）
/bots               L1 Bot 总览（默认落地页，S3）
/bots/:id           L1 Bot 详情：概览 / 记忆 / 权限边界 / 会话列表
/chats              L2 渠道索引（私聊 + 群聊 + 新建群聊）【补】
/chat/:channelId    L2+L3 会话视图（?session=id 为只读会话透镜）
/assignments        任务总览     /assignments/:id  任务详情
/schedules          定时任务     /usage            用量（Bot × 运行时）
/settings           运行时 / 安全 / 数据与保留 / 权限审计
```

**PRD 缺口（已补）**：P0-06 要求群聊有主持人与参与者集合，但 PRD 无渠道创建落点 → 补 `/chats`；私聊入口由 `/bots` 卡片直达。

### 2.2 全局框架
| 区域 | 承载 | 不承载 |
|---|---|---|
| 左侧栏 240px | 一级导航（Bot / 会话 / 任务 / 定时 / 用量 / 设置）；底部「待批权限 N」「执行中 N」徽标 | Bot 列表本身（只给计数，避免双份列表） |
| 顶部条 | 面包屑（Bot > 会话 > Session）、全局待批 chip、断线横幅 | 全局搜索（首版无） |
| 右侧面板 320px | 仅 `/chat` 与 `/assignments/:id`：记忆条数、边界、执行位置、Session 元信息 | 任何可编辑配置（配置回 Bot 详情） |

**全局待批 chip**：任一会话出现待批权限时亮起，浮层列出「Bot · 动作 · 剩余 87s」，点条目跳会话并滚动定位卡片——**浮层内不提供批准**（批准必须看到上下文）。

### 2.3 三层透镜（解决三维复杂性）
| 层 | 用户问题 | 出现在哪 | 只显示到哪 |
|---|---|---|---|
| L1 Bot | 这是谁、在什么上跑、现在忙吗 | `/bots` 卡片、`/bots/:id` 概览 | 不出现事件与消息内容 |
| L2 Session | 这次执行谁跑的、续接还是重建、花了多少 | 会话内 Session 分隔条、Turn 头、Bot 详情会话列表 | 不出现单条事件细节 |
| L3 Event | 它到底做了什么 | Turn 内折叠块、`/assignments/:id` 事件流 | 不出现其他 Bot 的其他 Session |

**规则**：L2 只在**发生变化**时显形——换运行时、resume 成功/重建、Session 结束、上下文被省略。日常连续对话不显示 Session 条。

### 2.4 Bot 卡片（S3 硬指标）
每卡 5 行，四项状态全部用**文字**呈现（不靠颜色区分运行时）：

```
+---------------------------------------------+
| [头像] 研究助手                    [改绑入口]|
|        用 Gemini 做竞品与论文调研             |  ← 人格摘要，1 行截断
|        运行时  Gemini CLI · ACP · 交互        |  ← 名称 + 协议 + 模式
|        执行位置 worktree  ~/.agentbot/wt/res |  ← 类型 + 实际路径（中段省略）
|        Session 空闲 · 2h 前        待批 2     |  ← 状态 + 相对时间 + 待批数
+---------------------------------------------+
```

- 页头汇总：`6 个 Bot · 3 种运行时 · 2 个执行中 · 3 条待批`（S3 第一眼信息）。主操作：进入会话（整卡可点）；悬停次操作：详情 / 派任务 / 更多。
- Session 状态四值：`空闲` / `生成中`（带已进行时长）/ `排队中`（带前序任务）/ `不可用`（运行时卸载或 worktree 未就绪，卡片顶部加细横幅）。100 个 Bot 网格虚拟化。

## 3. 核心流程

### F1 首次启动（S1：≤60s 到第一条消息）
入口：控制台打印的带 token URL（P0-14）。

| # | 用户看到 | 用户做 | 系统反馈 |
|---|---|---|---|
| 1 | 向导「检测你机器上的 agent」，逐项出现进度行（ZCode / Codex / Claude / Gemini / DSH） | 等待，可「跳过」 | 每项独立出结果：可用（名称+版本+路径）/ 未安装 / 检测超时（3s），互不阻塞 |
| 2 | 结果列表，可用的可勾选 | 选一个作默认运行时 | 能力行：plan / 权限请求 / resume 三格，值「支持」「不支持」「未知」 |
| 3 | 「给你的第一个 Bot 起名」：名称、人格（预填模板）、执行位置（默认 local） | 填名称，点「创建」 | 名称重复 → 内联报错不提交；成功直接进第三步 |
| 4 | 「发第一条消息」，输入框上方 `研究助手 · Gemini CLI · local ~/project` | 输入内容，发送 | 2s 内首个流式 token；结束显示 token 用量；顶部出现「完成，进入工作台」 |

失败分支：全部未安装 → 停在第一步给安装指引（每项一条命令 + 复制）+「手动添加」，不阻断进入工作台；单项探测超时 → 该项「检测超时 + 重试」，其余照常，不弹全屏错误；运行时未登录 → 错误块「Gemini CLI 还没登录。在终端运行 `gemini login` 后点重试」+ 复制命令，不丢已输入内容；首条消息失败 → 输入框恢复可用、可「重发」，向导不退出、允许换运行时。

### F2 群聊多 Bot 协作（S2）
入口：`/chats` →「新建群聊」（选 2–5 个 Bot、指定主持人，默认最早创建者）→ `/chat/:channelId`。

| # | 用户看到 | 用户做 | 系统反馈 |
|---|---|---|---|
| 1 | 群聊空态：参与者头像行 +「主持人：研究助手」+「主持人会决定谁来回答」 | 输入任务并发送 | 用户消息入流；主持人 Turn 折叠为一行「主持人在决定发言人…」 |
| 2 | 5s 内「本轮发言人」系统块：`研究助手（理由）、实现助手（理由）` | 无需操作（可「改由我指定」覆盖） | 未被点名 Bot 产生 0 次调用；块尾 `本轮调用 2/3` |
| 3 | 第一个 Bot 的 Turn 展开流式，Turn 头写 `研究助手 · Gemini · 交互` | 观察 | 其他在跑的 Bot 折叠为活动行 `实现助手 · 正在运行 npm test · 12s` |
| 4 | 第一个 Turn 结束收起为「完成 · 1.2k/0.4k」，第二个自动展开 | 继续观察，或停止某个 Bot | 停止只作用于该 Turn，其余不受影响 |
| 5 | 流尾「本轮小结」折叠块：谁说了什么一句、总用量、未发言 Bot 及原因（P1-06） | 阅读 | 可展开原因；无发言时显示「本轮无 Bot 发言 + 指定 Bot 回复」 |

失败分支：主持 Bot 不可用 → 系统提示「主持人不可用，本轮改为 @ 谁谁回」，@ 选择器自动展开；主持人返回不存在的 Bot → 丢弃并标「忽略 1 项（不存在）」；返回空列表 → 「本轮无 Bot 发言」+「指定 Bot 回复」。

### F3 从对话派活成 Assignment
入口：任意消息悬停 →「转为任务」（或 `/assignments` 的「新建」）。

| # | 用户看到 | 用户做 | 系统反馈 |
|---|---|---|---|
| 1 | 任务表单：标题（预填消息首句）、交付物描述、指派 Bot（默认当前）、执行位置（继承） | 确认提交 | 消息下贴状态卡 `已排队 · 研究助手 · 0s`；会话顶部细提示条「本会话有 1 个任务执行中」 |
| 2 | 状态卡随状态变化：排队中（含等待原因）/ 执行中（时长 + 当前动作摘要） | 继续聊天 | 执行不占输入框；任务事件不进主消息流，只进卡片计数 |
| 3 | 完成后卡变「已完成」并展开报告摘要：执行摘要 3 行、改动文件 N 个、用量一行 | 点「查看完整报告」 | 跳 `/assignments/:id`；返回时会话停在原位 |
| 4 | 用户离开页面再回来 | 打开会话 | 卡片显示最新状态 +「期间发生了什么」（N 条事件、最后活动时间），不补播流式动画 |

失败分支：同 Bot 已有 2 个任务 → 「等待前序任务（队列 2/5）」；超 5 个 → 提交时拒绝并说明上限；30 分钟未结束 → 标「超时」保留已有产出，主操作「查看产出 / 重跑」；崩溃 → 标失败，报告附最后 50 条事件。

### F4 权限卡片决策
入口：运行时在任一会话发起授权请求。

| # | 用户看到 | 用户做 | 系统反馈 |
|---|---|---|---|
| 1 | 1s 内卡片插入该 Turn，输入框锁定「等待你批准，无法继续发送」；不在该会话时顶部 chip 亮起并计数 | 点 chip 跳转，或本就在场 | 卡片显示动作类型（写文件 / 执行命令 / 联网）、目标绝对路径或完整命令、来源 Bot、剩余秒数（120s 倒计时） |
| 2 | 四按钮：`批准一次` `拒绝` `记住（本会话）` `记住（本 Bot 永久）`；批准一次为主操作 | 选择（或 A / R / Shift+A） | 1s 内转已决态「已批准 · 你 · 14:32」；输入框解锁，流继续 |
| 3 | 卡片收起为一行审计行（可展开看完整动作与决定） | 无 | 记录写入 `/settings` 权限审计 |
| 4 | 请求超出 Bot 边界 | 无决策按钮 | 标「超出 Bot 边界 · 已自动拒绝」+「去调整边界」；不转发运行时，不占 120s |

失败分支：`reject` 策略下 120s 无操作 → 自动拒绝并标「超时自动拒绝」，Turn 尾提示「任务可能因此中断，可重发」；`hold` 策略下不超时拒绝，卡片持续挂起（最长 24h），用户回来仍可决策，期间运行时进程退出则转「请求已失效」；运行时已退出 → 标「请求已失效」，按钮全禁；同动作 60s 内重复且已「记住」或 `preauth` 命中 → 不再弹卡，只留一行「自动批准（已记住）」。

### F5 Bot 换绑运行时
入口：`/bots/:id` 概览 →「改绑运行时」。

| # | 用户看到 | 用户做 | 系统反馈 |
|---|---|---|---|
| 1 | 对话框：运行时下拉（不可用项置灰 + 原因：未安装 / 需要 ≥x.y / 健康检查失败） | 选一个新运行时 | 下半部出现**能力差异预览**：`将获得：resume、计划` / `将失去：权限请求`；提示「人格与记忆保留，新 Session 开始」 |
| 2 | 确认改绑 | 点「改绑」 | 概览徽标立即更新，能力行同步；执行位置与 worktree 路径保留（新运行时不支持 worktree 则提示并可改回 local） |
| 3 | 回到会话 | 发一条消息 | 出现 Session 分隔条 `新 Session · 已重建上下文（人格 + 记忆 + 最近 20 条）`；Bot 名与头像不变 |
| 4 | 打开记忆标签 | 检查 | 记忆条目一条未少，每条仍标来源 Session（旧 Session 可点开只读） |

失败分支：新运行时健康检查失败 → 允许改绑但卡片标「运行时不可用」，发送被阻止并给改绑入口；改绑时有进行中 Turn → 提示「当前回复将被中断」，确认后旧 Turn 标「已中断」。

### F6 定时任务（P0-11）
入口：`/schedules` →「新建」；会话内「更多 → 设为定时」可预填目标会话。

| # | 用户看到 | 用户做 | 系统反馈 |
|---|---|---|---|
| 1 | 表单：名称、目标 Bot、目标会话、任务内容、触发方式（延迟 N 分钟 / 每 N 分钟 / 每日 HH:MM） | 填写保存 | 周期 <5 分钟内联拒绝；保存后显示「下次触发 明天 09:00」 |
| 2 | 到点触发 | 无操作 | 目标会话追加系统块 `定时任务「竞品周报」触发 · 研究助手`，其后是该 Bot 的 Turn；列表「上次结果」变「成功 · 3m 前」 |
| 3 | 服务当时未运行 | 无操作 | 启动后补跑 1 次并标「补跑」，不重复补跑 |

失败分支：连续失败 3 次 → 自动暂停，行变灰并显示原因与「恢复」；Bot 被删 → 标「目标 Bot 已删除」，提供改绑或删除。

### 4.1 六个非重点页（每页四态顺序：空 / 加载 / 正常 / 错误）
| 页 | 分区与元素 | 主操作 | 四态 |
|---|---|---|---|
| `/setup` | 单列居中；顶部三步进度条，底部固定「上一步 / 下一步」；元素：探测列表（名称、版本、路径、状态、重试）→ 能力行 → Bot 表单 → 首条消息框 | 每步一个（继续 / 创建 / 发送） | 空＝「正在检查…」；加载＝每行独立骨架不整页转圈；正常＝三步全通；错误＝单项失败就地标注可跳过 |
| `/chats`【补】 | 单列列表 +「新建群聊」；分私聊 / 群聊两组；行＝渠道名（群聊显示参与者头像叠加）、最后一条摘要、时间、未读数、待批小圆点 | 新建群聊（选参与者 + 选主持人） | 空＝「还没有会话，从任一 Bot 卡片开始私聊」；加载＝5 行骨架；正常＝列表；错误＝重试条 |
| `/assignments` | 状态分组标签（排队 / 执行中 / 已完成 / 失败 / 超时，带计数）+ 列表；列＝标题、指派 Bot（含运行时徽标）、来源会话、耗时、用量 | 无全局主操作（创建在会话内），右上角仅「从会话派活」说明链接 | 空＝说明「任务从会话里的一条消息创建」+ 示例图示；加载＝分组骨架；正常＝列表；错误＝重试条 |
| `/assignments/:id` | 上＝任务头（标题、Bot、状态、耗时、用量）+ 操作区；中＝报告正文；右＝事件流时间线（窄屏折为底部抽屉）；报告＝执行摘要、改动文件列表、用量，失败时附「最后 50 条事件」 | 重跑（仅失败 / 超时） | 空＝「等待前序任务（第 2 位）」+ 前序链接；加载＝报告生成中显示进度（已完成事件数）；正常＝完整报告；错误＝失败原因一句 + 事件流 + 重跑 |
| `/schedules` | 列表 + 新建抽屉；行＝名称、目标 Bot、目标会话、触发规则、下次触发、上次结果、启停开关 | 新建 | 空＝「还没有定时任务」+ 新建；加载＝行骨架；正常＝列表；错误＝顶部横幅「调度器异常，定时任务可能不会触发」+ 重试 |
| `/usage` | 筛选条（时间范围 / Bot / 运行时）+ 聚合表 + 未上报单列 + 导出（P1）；行＝Bot × 运行时，列＝请求数、输入 token、输出 token、模式倍率提示（headless 约 3×），已删除 Bot 单独标记 | 无（纯查看），导出为次操作 | 空＝「还没有可统计的调用」+ 一句说明；加载＝表格骨架；正常＝表格；错误＝「查询失败」+ 重试并保留筛选条件 |

### 4.2 `/bots` Bot 总览（S3，重点页）
- **分区**：顶部汇总条 + 筛选条（运行时 / 状态 / 执行位置）+ 卡片网格（≥1280 三列，1024–1280 两列）。
- **元素层级**：① Bot 名称 ② 运行时徽标（文字）③ Session 状态 + 待批数 ④ 执行位置路径 ⑤ 人格摘要（卡片结构见 §2.4）。
- **主操作**：新建 Bot；次操作卡片悬停出现。
- **四态**：空＝大号引导「创建你的第一个 Bot」+ 三行说明什么是 Bot；加载＝同尺寸骨架 6 张；正常＝如上卡片；错误＝整页错误条「读取 Bot 失败」+ 重试，保留导航。筛选无结果时显示「没有符合条件的 Bot」+「清除筛选」，不复用空态引导。

### 4.3 `/bots/:id` Bot 详情（重点页）
- **分区**：头部身份区（头像 / 名称 / 运行时徽标 / 执行位置 / 状态）+ 四标签。
- **概览**：能力行（plan / 权限请求 / resume + 上下文窗口）、当前 Session 卡（续接状态、开始时间、用量）、最近 3 条会话、危险区（删除需输名称并选「一并删除 / 归档保留」）。
- **记忆**：条目列表（内容、来源会话、更新时间、注入开关）；顶部「本轮注入估算 3,120 / 6,000 字符」；「新增」「立即摘要」；摘要条目单独标记可编辑。
- **权限边界**：允许目录（绝对路径）、允许 shell、允许联网、预授权列表、「写操作自动批准」（二次确认 + 风险文案）、边界拒绝记录（只读）。
- **会话列表**：时间、运行时、续接状态、消息数、用量、只读入口。
- **主操作**：概览为「进入会话」；其余标签各自一个（新增记忆 / 保存边界）。

## 5. 统一事件流呈现规格
| # | 事件 | 权重 | 默认 | 一行摘要示例 | 展开后 |
|---|---|---|---|---|---|
| 1 | 消息增量 | 主 | 展开（正文） | — | 流式追加，行内光标，结束去光标 |
| 2 | 思考 | 次 | 折叠 | `思考 8s · 214 字` | 全文，灰底等宽，可复制 |
| 3 | 工具调用 | 次 | 折叠 | `Read src/auth.ts` / `Bash: npm test` | 完整参数（截断 20 行 + 查看全部）、开始时间 |
| 4 | 工具结果 | 次（挂调用下） | 折叠 | `成功 · 42 行输出` / `失败 · exit 1` | 输出全文（超 200 行截断）、退出码 |
| 5 | 计划 | 次（中） | 折叠 | `计划 5 项 · 3 完成` | 清单，每项状态（待办 / 进行 / 完成） |
| 6 | 权限请求 | 主（阻断时） | 常显卡片 | — | 已决后收为 `已批准 · 你 · 14:32` |
| 7 | 用量 | 极轻 | 常显单行 | `1,204 in / 388 out · 交互 ×1` | 无展开（附 Turn 尾） |
| 8 | 结束 | 极轻 | 常显状态戳 | `完成 · 12.4s` | 无 |
| 9 | 错误 | 主 | 常显 | 人话一句（见 6.3） | 技术细节（运行时原文、exit code）折叠 |

**规则**：只有 1 / 6 / 9 默认占据视觉主导，2–5 / 7–8 折为一行，避免长任务撑爆流；**不出现空块**——运行时未声明某类事件，该类型在流中完全不存在，筛选器里也不出现；未知事件 → 一行 `未知事件（runtime.xyz）` 折叠块，展开显示原始 JSON，不报错不丢弃；连续 30s 无事件且未结束 → Turn 内插 `无响应 · 已 30s` + 停止按钮（不是错误块，可恢复）；单轮 >2000 条事件用虚拟滚动，Turn 头吸顶。

### 5.1 群聊多 Bot 同时输出（防刷屏）
1. **身份锚点**：Turn 头（头像 + 名称 + 运行时徽标）在该 Turn 滚动时吸顶，任何时刻都知道在谁的内容里。
2. **单展开原则**：同一时刻最多一个 Turn 展开流式；其他运行中的 Bot 折叠为活动行 `实现助手 · 正在运行 npm test · 12s`，可点开接管。新 Turn 开始时自动收起旧的（用户手动展开过的 5 分钟内不抢焦点）。
3. **顺序优先**：主持人返回名单后默认**依次执行**，仅用户显式 @ 多个 Bot 时才并行——减少互相覆盖文件，阅读顺序稳定。
4. **轮次栅栏**：每轮结束插极轻分隔行 `— 本轮结束 · 3 个 Bot · 4,120 token —`，历史永远按轮可读。
5. **成本可见**：主持人块尾固定显示 `本轮调用 2/3`。

## 6. 交互反馈规则

### 6.1 流式节奏与长任务
- 增量按帧合并渲染（不逐字重排）；正文末尾闪烁光标；首 token 超 2s 时 Turn 内显示 `等待首个响应 · 已 Ns`。
- **停止按钮**：生成中替换发送，位置固定不变（避免误点）；点击 1s 内发 cancel，已生成内容保留并标「已中断」。
- **非流式运行时**：Turn 一开始显示 `该运行时一次性返回，预计 30–60s` + 已等待时长；不显示假光标。
- **离开再回来**：不重播动画，Turn 直接以最终状态渲染；执行中的任务卡显示「期间发生了什么」（事件数、最后活动时间、当前动作摘要）。
- **全局可见性**：左侧栏「执行中 N」徽标 + `/assignments` 分组计数同步；任务完成但用户不在该会话 → 列表出现新条目、会话行出现未读标记，不弹全局弹窗。

### 6.2 权限卡片紧迫感分级
| 级别 | 触发 | 表现 | 输入框 |
|---|---|---|---|
| L1 阻断 | 运行时正在等待，Session 已暂停（`reject` 策略） | 卡片固定在输入框上方，倒计时常显，按钮区唯一焦点 | 锁定，显示「等待你批准」 |
| L1-hold 挂起 | `hold` 策略（Assignment / 定时任务）下运行时等待 | 卡片无倒计时，显示「等待你回来 · 已挂起 1h 20m」，附「最长保留 24h」；按钮区同 L1 | 该会话输入框可用（不锁），但该 Turn 显示「挂起中」 |
| L2 已自动处置 | 超出边界 / 超时 / 已记住或 `preauth` 自动批准 | 流内一行告知，无按钮，可展开 | 不锁定 |
| L3 已失效 | 运行时已退出（含 hold 期间进程退出） | 灰化卡片，按钮禁用，附「该请求已失效」 | 不锁定 |

### 6.3 错误的人话表达
| 情况 | 文案结构 |
|---|---|
| 运行时崩溃 | 「实现助手 的执行进程退出了（exit 1）。这一轮没有完成。」+ 主「重发」+ 次「查看详情」 |
| 超时 | 「超过 30 分钟没有结束，已标记超时。已有产出保留。」+「查看产出 / 重跑」 |
| 边界拒绝 | 「这个动作超出了 研究助手 的权限边界（写 /etc），已拦截，没有发给运行时。」+「去调整边界」 |
| 运行时未登录 | 「Gemini CLI 还没登录。在终端运行 `gemini login` 后点重试。」+ 复制命令 |
| 连接断开 | 「和本地服务的连接断开了，正在重连。」+ 重连状态；恢复后从最后一条已落库事件继续，不重复消息 |
| 运行时不可用 | 「这个 Bot 绑定的运行时当前不可用（未安装 / 健康检查失败）。」+「改绑运行时」 |

原则：一句话说「发生了什么 + 我的内容还在吗 + 我能做什么」，技术原文折叠进「详情」。

## 8. 无障碍与键盘
- **键盘可达**：卡片、折叠块、Turn 头均可聚焦，`Enter/Space` 展开收起，折叠块带 `aria-expanded`。
- **焦点顺序**：左导航 → 会话头 → 消息流（按 Turn 顺序）→ 权限卡片 → 输入区。权限卡片出现**不强制抢焦点**，但顶部出现可聚焦提示条；`F6` 直达卡片。
- **权限快捷键**（阻断态全局生效，界面常显提示）：`A` 批准一次 / `R` 拒绝 / `Shift+A` 记住本会话 / `Ctrl+Shift+A` 记住本 Bot 永久（再确认一次）/ `Esc` 收起详情。快捷键必须在卡片上以文字标注。
- **虚拟滚动**：焦点移出可视区时先滚动到焦点再渲染，绝不丢焦点；屏幕阅读器用户可「跳过流式」跳到下一 Turn。
- **事件流的屏幕阅读器处理**：正文 `aria-live="polite"` 但**按段落节流**（每完成一段或 Turn 结束播报一次），绝不逐 token 播报；Turn 开始播报「研究助手，Gemini，开始回复」；折叠块播报「工具调用 Read src/auth.ts，已折叠，可展开」。
- **摘要替代**：每个 Turn 提供「本轮摘要」，输出线性文字版（谁、做了什么、结果、用量）。
- **对比度与动效**：不靠颜色区分运行时（一律带文字）；尊重 `prefers-reduced-motion`，关闭光标闪烁与自动展开动画。

- 列出技能目录里的全部技能，逐项开关；带「内置」徽标的来自基础技能包。
- 「全部启用」= `enabledSkills: null`（老 Bot 的默认）；「全部停用」= `[]`。用户动过任意一项后就是显式白名单，关掉最后一个不会变成「全开」。
- 停用的技能不进系统提示索引，但模型仍可用 `list_skills` 发现、`read_skill` 读取。
- 改动下一轮对话生效（扫描按 mtime 自动失效），不需要重启。
