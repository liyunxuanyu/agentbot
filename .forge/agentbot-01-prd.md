# AgentBot 需求规格

> 输入：`agentbot-00-brief.md`、`agentbot-ref-research.md`、`state.json` chosen.brief（6 条已决）。
> 本文件只定义「做什么、怎么算做完」，不含界面视觉、技术选型、排期。

## 1. 产品概述

单用户本地 Web 工作台：用户创建一组有名字、人格、记忆和权限边界的 Bot，每个 Bot 绑定本机已安装的 agent 运行时（ZCode / Codex / [CC] / Gemini CLI / DSH 等）；本产品只负责编排、呈现、审计与治理，执行永远交给运行时。首版价值成立的条件只有一个：同一群聊里不同 Bot 跑在不同运行时上，且 Bot 换运行时后人格与记忆不丢。

> **后续修订（2026-10-26 起）**：新增第四条运行时通道 `builtin`（内置引擎）——它**在服务进程内自带 agent loop**，直连模型 API，不启动子进程。这修正了本文件与 brief 的「自己不实现 agent loop」：外部 CLI/ACP/原生通道仍然「执行交给运行时」，内置引擎是并存的第四条通道，用于低成本、可逐次拦截权限的本地对话。详见 `.forge/agentbot-06-builtin-engine.md`。

**首版成功判据（可验收）**

| # | 判据 | 判定方式 |
|---|---|---|
| S1 | 冷启动到发出第一条消息 ≤ 60s，全程不编辑任何配置文件 | 新装环境计时 |
| S2 | 一次群聊中 ≥3 个 Bot、≥2 种运行时完成一个 Assignment 并交回报告，人工介入 ≤1 次（仅权限批准） | 演练一次并记录介入次数 |
| S3 | Bot 列表一屏显示每个 Bot 的运行时、执行位置、session 状态；抽查 5 个 Bot，用户 100% 能正确说出它在哪个 agent 上跑 | 人工抽查 |
| S4 | 新增一个原生 ACP 运行时：≤1 个 adapter 声明文件、≤200 行、零核心改动、零 schema 变更；从零到该运行时在群里回第一条消息 ≤1h | 新增 Gemini CLI 计时验证 |

## 2. 角色与用户故事

| # | 角色 | 用户故事 |
|---|---|---|
| U1 | 独立开发者 | 作为独立开发者，我要在群里 @ 一个 Bot 派活并让它独立执行后交回报告，以便我去开会时任务继续推进。 |
| U2 | 独立开发者 | 作为独立开发者，我要让研究 Bot 用 Gemini、实现 Bot 用 Codex、审查 Bot 用 [CC] 同处一个群，以便每个阶段用最合适的运行时而不人肉搬上下文。 |

| U10 | 任何用户 | 作为用户，我要在 Bot 请求写文件或跑命令时看到卡片并能拒绝，以便无人值守时不会误删东西。 |

## 3. 功能分级

### P0（首版必须，缺了产品不成立）

| ID | 能力域 | 功能 | 为何是 P0 |
|---|---|---|---|
| P0-01 | 运行时接入 | 运行时发现、注册、健康检查 | 没有已装 agent 就没有执行能力 |
| P0-02 | 运行时接入 | 能力上报与绑定可用性（徽标/置灰） | C3：假按钮会让用户以为产品坏了 |
| P0-03 | Bot 实体 | Bot 创建/编辑/删除、人格、头像、运行时绑定 | Bot 是产品的唯一主体 |
| P0-04 | 私聊 | 流式输出、中断、重发 | 最基础的可用性 |
| P0-05 | 事件流 | 9 类事件统一呈现 | C5：多运行时共存的前提 |
| P0-06 | 群聊 | 主持 Bot 决定谁发言、@ 指定、防全员回复 | 核心差异体验 + 成本控制 |
| P0-07 | 任务委派 | Assignment 独立执行并交回报告 | 「AI 同事」而非聊天框的关键 |
| P0-08 | 权限 | 权限卡片（批准/拒绝/记住） | C4：无人值守的安全底线 |
| P0-09 | 权限 | Bot 级目录/工具边界与预授权 | 同上，且是差异点 |
| P0-10 | 记忆 | 记忆条目查看/编辑/自动摘要/注入 | 换运行时记忆不丢 = 核心价值 |
| P0-11 | 定时任务 | 一次性延迟 + 周期触发（最小版） | 不做则退化为聊天工具（已决进首版） |
| P0-12 | 用量 | 按 Bot × 运行时统计 | C6：成本必须可见 |
| P0-13 | 执行位置 | local / git worktree 选择 | C7：用户必须知道 Bot 改了哪个目录 |
| P0-14 | 安全 | 本地服务 token 鉴权 | 防同机其他程序读取会话 |
| P0-15 | 会话归属 | 产品层会话真相 + resume 降级重建 | 运行时不可靠，持久性不能押在它身上 |

| ID | 功能 | 验收要点 |
|---|---|---|

### P2（明确推迟）

容器/远程执行位置；IM 平台接入；Bot 市场与导入导出 zip；常驻 Routine 轮询；多用户/团队/SSO；移动端与桌面客户端；记忆 Git 可视化；Bot 主动发起对话。

## 4. 每条 P0 的验收标准与边界

| ID | 功能点 | 验收标准 | 边界处理 |
|---|---|---|---|
| P0-01 | 运行时发现 | 打开运行时管理页，5s 内列出 PATH 中探测到的 ZCode / Codex / Claude / Gemini / DSH 条目，每项显示名称、版本、可执行路径、状态（可用/未安装）；单项探测超时 3s，互不阻塞；支持手动添加自定义启动命令。 | 探测超时：该项显示「检测超时」+ 重试按钮，其余项正常展示。重复添加同一可执行文件：提示「已存在」并跳转到该条目。 |
| P0-02 | 能力上报 | 选中运行时后展示 3 个能力徽标（plan / 权限请求 / resume）与上下文窗口；能力值来自运行时上报，未上报显示「未知」而非隐藏；未安装或健康检查失败的运行时在下拉中置灰并显示原因文本。 | 版本低于 adapter 声明的最低版本：置灰 + 原因「需要 ≥ x.y」。健康检查 10s 无响应：标记 unhealthy，历史会话仍可读，发送按钮禁用并提示。 |
| P0-03 | Bot 实体 | 创建需填名称（1–32 字符，工作区内唯一）、人格（≤4000 字符）、运行时；保存后出现在 Bot 列表，卡片显示头像、名称、运行时、执行位置、session 状态；编辑人格后下一条消息即生效（不重启服务）；删除需输入 Bot 名称二次确认。 | 名称重复：内联报错不提交。绑定的运行时已卸载：Bot 保留，卡片标「运行时不可用」，发送被阻止并给「改绑」入口。删除时需显式选择「一并删除会话/记忆/定时任务」或「归档保留」。 |
| P0-04 | 私聊流式 | 发送后 2s 内 UI 出现首个流式 token；结束后状态由「生成中」变「完成」并显示本轮 token 用量；点「停止」后 1s 内向运行时发出 cancel，已生成内容保留并标「已中断」；「重发」以上一条用户消息原文新建一轮，原轮次不覆盖。 | 运行时进程崩溃：该轮标「失败：运行时退出（exit code N）」，输入框恢复可用。浏览器连接断开：重连后从最后一条已落库事件继续渲染，不重复消息。空回复：显示「未返回内容」+ 重发。 |
| P0-05 | 统一事件流 | 运行时在能力探测阶段声明**事件能力掩码**（它实际会产出哪几类事件）；UI 按声明的集合呈现 9 类事件（消息增量、思考、工具调用、工具结果、计划、权限请求、用量、结束、错误），不同样式块且可折叠；同一轮内顺序与运行时上报顺序一致；**未声明的事件类型在流中完全不出现、不出现空块、不报错**；已声明类型内字段无法解析时降级渲染为「未知事件」折叠块并保留原始 JSON，不丢弃。 | 单轮事件 >2000 条：虚拟滚动，仅渲染可视区 ±50 条。事件缺必填字段：降级渲染并记 warning，不中断整轮。连续 30s 无事件且未结束：显示「无响应」并提供停止。运行时未声明任何事件类型（纯 CLI 无结构输出）：整轮降级为「仅最终文本 + 原始 stdout 折叠」模式并明示。 |
| P0-06 | 群聊主持 | 群聊必须指定 1 个主持 Bot（默认最早创建者）；用户发消息后主持人输出发言人列表（0–3 个）及理由，**决策超时默认 20s**（`AGENTBOT_GROUP_DECISION_MS` 可调）；未被点名 Bot 产生 0 次运行时调用；用户 @ 某 Bot 时该 Bot 必被包含且优先；单条用户消息触发的 Bot 调用总数 ≤3。 | 主持 Bot 运行时不可用：降级为「@ 谁谁回」并在群内显示系统提示。主持人返回不存在的 Bot：丢弃该项、按剩余合法名单执行并记 warning。返回空列表：显示「本轮无 Bot 发言」+「指定 Bot 回复」按钮。 |
| P0-07 | Assignment | 可从一条消息转为 Assignment（标题 + 交付物描述 + 指派 Bot）；独立线程执行，聊天流只显示状态卡片（排队/执行中/已完成/失败）；完成后生成 Markdown 报告（执行摘要、改动文件列表、用量）并回贴原会话；执行中会话可继续聊天。 | 同一 Bot 同时 **1 个** Assignment 执行，第二个起排队显示「等待前序任务」，队列上限 5，超出拒绝（并发 1：local 模式下并发写同目录有真实冲突风险）。30 分钟无结束事件：标「超时」并保留已有产出。运行时崩溃：标失败，报告附最后 50 条事件。 |
| P0-08 | 权限卡片 | 运行时请求授权后 1s 内出现卡片，显示动作类型、目标路径/命令、来源 Bot、剩余处置时间；按钮为「批准一次 / 拒绝 / 记住（本会话）/ 记住（本 Bot 永久）」；选择后 1s 内回传运行时，卡片转为已决状态并写审计（时间、Bot、动作、决定、操作者）。**超时策略按 Bot 配置三档**：`reject`（交互会话默认，120s 后拒绝）、`hold`（Assignment 与定时任务默认，不拒绝不继续，Session 挂起最长 24h，用户回来仍可决策）、`preauth`（用户显式开启，边界内写操作自动批准只写审计，边界外仍走 hold/reject）。 | `reject` 超时：按拒绝回传并标「超时自动拒绝」。`hold` 超时 24h：转拒绝并标「挂起超时」。`hold` 期间运行时进程已退出：卡片直接转「请求已失效」，不占满 24h。运行时已退出：卡片标「请求已失效」。同一动作 60s 内重复且已有「记住」：自动批准不再弹卡，但仍写审计。 |
| P0-09 | Bot 边界 | Bot 详情可配：允许目录（绝对路径列表）、是否允许 shell、是否允许联网，默认全关（只读 + 写需批准）；请求超出边界时在产品层直接拒绝、不转发运行时，卡片标「超出 Bot 边界」；对单个 Bot 开启「写操作自动批准」需二次确认并展示风险文案。 | 目录不存在或不可写：保存时内联报错。请求为相对路径：先解析为绝对路径再判定，无法解析即拒绝。边界变更只影响之后请求，进行中请求按旧版本判定并记录版本号。 |
| P0-10 | 记忆 | 记忆页列出条目（内容、来源会话、更新时间、是否注入），可增/改/删，保存后 1s 内生效；每轮注入「人格 + 标记注入的记忆」，总字符 ≤6000，超出按更新时间倒序截断并显示「已截断 N 条」；Session 消息数达 40 或用户点「立即摘要」时生成 ≤500 字符摘要条目，标「自动摘要」且可编辑。 | 记忆为空：显示空态 + 新增按钮，不注入空段落。摘要时运行时不可用：保留待摘要标记，下次会话开始前重试，不阻塞对话。删除记忆只影响后续注入，历史消息不变。 |
| P0-11 | 定时任务 | 创建需填名称、目标 Bot、任务内容、触发方式（一次性延迟 N 分钟 / 周期 every N 分钟或每日 HH:MM）；到点以该 Bot 身份在指定会话执行并追加结果消息；列表显示下次触发时间与上次结果；支持暂停/恢复/删除。 | 服务未运行错过触发：启动后补跑 1 次并标「补跑」，不重复补跑。周期任务连续失败 3 次：自动暂停并显示原因。周期最小间隔 5 分钟，更小则拒绝保存。一次性任务执行后置「已完成」并保留记录。 |
| P0-12 | 用量统计 | 用量页可按 Bot × 运行时聚合，显示请求数、输入/输出 token，支持今天/7 天/30 天/全部筛选；每条记录标注模式（headless / 交互）与倍率提示；每轮结束后 5s 内可见；无数据显示空态而非空表格。 | 运行时未上报：记为「未上报」，不估算，聚合时单列。同时上报累计值与增量：以增量为准，差值 >10% 记 warning。删除 Bot 后历史用量默认保留并标「已删除 Bot」，可在设置中一并删除。 |
| P0-13 | 执行位置 | 创建/编辑 Bot 可选 local 或 git worktree；选 worktree 需填仓库根路径，保存时校验为 git 仓库；首个 Session 创建独立 worktree，Bot 详情显示实际路径；Bot 列表与详情均显示执行位置；同一 Bot 后续 Session 复用同一 worktree。 | 路径非 git 仓库：保存失败并提示。worktree 创建失败（磁盘满/权限）：Bot 可保存但标「worktree 未就绪」，发送时阻止并给重试。两个 Bot 指向同一仓库：允许，各自独立 worktree。 |
| P0-14 | 本地鉴权 | 首次启动生成 ≥32 字节随机 token，写入仅当前用户可读的本地文件并在控制台打印访问地址；无 token 或错误 token 的 HTTP 请求返回 401 且不含任何业务数据；**实时推送连接握手时校验 token，失败即 401 并立即断开**（实现为 SSE）；UI 刷新不需重新输入 token。 | token 文件被删：下次启动重新生成并使旧 token 失效。同一来源连续 10 次失败：60s 内返回 429。手动重置 token：10s 内断开所有已连接客户端并要求用新 URL。 |

> **P0-14 实现现状（2026-10-28）**：控制台打印的是**登录页地址** `http://127.0.0.1:<port>/login`
> （另附一条 `?t=<token>` 链接）；用户输入令牌后服务端种 **30 天持久 HttpOnly cookie**
> （SameSite=Strict，HTTPS/生产加 Secure），之后刷新与重开浏览器都不再需要 token。
> 未登录的**浏览器导航**不再看到一屏 JSON，而是 302 到 `/login?next=<原路径>`；`/api/*` 与
> fetch/EventSource 仍回 `401 {"error":"unauthorized"}`。新增 `GET/POST /login`、`POST /logout`、
> `POST /api/auth/logout`（后两者只删凭证、免鉴权）。详见 `.forge/agentbot-05-architecture.md` §8。
| P0-15 | 会话真相与恢复 | 每轮消息、事件、权限决定在收到后 1s 内落库；重启服务后会话完整恢复（顺序、状态、用量一致）；新 Session 优先尝试运行时 resume，成功则标「已续接上下文」；resume 失败或不支持时由产品层重建（人格 + 记忆 + 最近 20 条消息），标「已重建上下文」，不向用户报错中断。 | 重建内容超出上下文窗口：从最早消息开始丢弃至估算 token < 窗口 70%，并显示「已省略 N 条历史」。崩溃后重发：开新 Session，旧 Session 保留只读。同一 Bot 两标签页同时发消息：以 Session 为锁串行，第二个显示「排队中」。 |

## 6. 数据要求

| 实体 | 关键字段 | 生命周期 |
|---|---|---|
| Bot | id、name、persona、avatar、defaultRuntimeId、executionLocation、repoPath、status | 创建→编辑→删除（可归档）；跨 Session 不变 |
| RuntimeDefinition | id、adapterName、version、command、protocol、capabilities、minVersion、healthStatus | 探测/手动添加时创建；卸载后保留并标不可用 |
| RuntimeBinding | botId、runtimeId、location、worktreePath、boundAt、unboundAt | 每次改绑新增一条；历史可查 |
| Channel | id、type（dm/group/task）、name、participantBotIds、hostBotId | 随 Bot/群创建；群主 Bot 删除时需重选主持人 |
| Session | id、botId、channelId、runtimeSessionId、resumeState（resumed/rebuilt/fresh）、startedAt、endedAt | 每次执行新建；Bot 改绑即新 Session |
| Message | id、sessionId、channelId、role、content、status、tokens、createdAt | 随会话；删除会话时级联 |
| Event | id、sessionId、messageId、type（**9 类可渲染事件 + `meta` 内部状态**）、payload、seq、createdAt | 与 Message 同生命周期；seq 保证顺序。`meta` 落库但不进渲染流、不计入事件能力掩码、不占 UI 位置 |
| Assignment | id、title、deliverable、botId、sourceChannelId、status、report、startedAt、endedAt | 排队→执行→完成/失败/超时；保留至用户删除 |
| MemoryEntry | id、botId、content、sourceSessionId、kind（manual/summary）、injected、updatedAt、version | 可编辑、可删除；摘要保留 5 版（P1） |
| Schedule | id、name、botId、channelId、prompt、triggerType、intervalMinutes/delayMinutes/atTime、nextRunAt、lastResult、enabled | 一次性执行后置已完成；周期可暂停 |
| PermissionRequest | id、sessionId、botId、action、target、decision、timeoutPolicy（reject/hold/preauth）、heldSince、decidedBy、decidedAt、expiresAt | 120s（reject）或 24h（hold）超时转拒绝；审计不可在 UI 删除 |
| UsageRecord | id、botId、runtimeId、sessionId、mode、inputTokens、outputTokens、reported | 每轮一条；按保留策略清理 |

**必须可导出**：UsageRecord（CSV）、Message + Event（按 Session 导出 JSON）、MemoryEntry（Markdown）。
**必须可删除**：单条 Session（含 Message/Event）、单个 Bot（级联会话/记忆/定时任务/绑定，用量可选保留）、全量数据（设置页，需输入确认短语）。
**保留策略**：消息与事件默认永久，设置可选 90/180/365 天自动清理；用量记录 365 天；权限审计 365 天；删除 Bot 时 worktree 保留 7 天后提示清理（不自动删用户文件）。

> **实现现状**：保留期数值在 `config.retention` 里，但**自动清理尚未实现**（没有调度任务调用
> `deleteOlderThan()`，也没有保留策略端点）；设置页的 90/180/365 单选不落库，页面已明示。
> 目前删除数据只有「数据整理」（孤儿数据，`/api/admin/tidy`）与「全量删除」（`/api/admin/purge`）。

## 7. 非功能要求

| 维度 | 要求 |
|---|---|
| 性能 | 冷启动到可发消息 ≤60s；首 token 到 UI ≤2s `[假设]`；Bot 列表 100 个 ≤1s 渲染；打开 1000 条消息的会话 ≤1.5s；用量聚合查询 ≤2s；权限卡片出现 ≤1s。 |
| 可靠性 | 单个运行时崩溃不导致服务进程退出，也不影响其他 Bot；每轮事件即时落库；服务重启后会话可完整恢复；每个 adapter 必须有契约测试（用录制的运行时事件样本回放）；未知协议行一律降级丢弃并记 warning，不抛致命错误。 |
| 安全 | 本地 HTTP/WS 全部 token 鉴权；Bot 边界默认全关；路径一律解析为绝对路径后再判定，禁止目录穿越；不存储、不代管任何运行时凭据或模型 API Key；审计记录只可导出、不可在 UI 内删除。 |
| 可扩展 | 新增原生 ACP 运行时 ≤1 个 adapter 声明文件、≤200 行、零核心改动、零 schema 变更，≤1h 能回第一条消息（S4）；adapter 契约包含：启动命令、协议类型、能力位、事件映射、版本下限；能力缺失时 UI 自动降级而非报错。 |
